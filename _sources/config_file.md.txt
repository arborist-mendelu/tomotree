# Configuration file `config.yaml`

Each dataset directory can contain an optional `config.yaml` file that
pre-configures the TomoTree application for that particular measurement.
When the directory is loaded the file is parsed and its values are written
directly into the application's session state, so every subsequent slider,
radio button, or toggle in the sidebar already shows the correct setting for
the dataset.

---

## Location

Place the file inside the measurement directory, for example:

```
streamlit_user/my_project/Measurement_01/
├── config.yaml          ← here
├── nodes.csv
├── speeds.csv
└── photo.jpg
```

---

## Input data

### Node positions

Provide either **Cartesian coordinates** or **pairwise distances**;
the application uses whichever key is present.

If neither key is present the application looks for files named

**`clockwise`** controls the orientation when computing positions from distances:

```yaml
clockwise: false   # true → clockwise node numbering
```

## Units

```yaml
length_unit: m      # m | cm | mm  (default: m)
time_unit: s        # s | ms | µs   (default: s)
```

**Legacy alternative** (deprecated, prefer the keys above):

```yaml
conversion factors:
  length: 0.01      # multiplier to convert to metres
  time: 1.0e-6      # multiplier to convert to seconds
```

## Access control

Each user can only see his/her own datasets and the datasets preloaded by the admin for all users. 

The admin can restrict the access to these *preloaded datasets* using the `allowed` key, which takes a list of usernames as its value. For example:

```yaml
allowed: [alice, bob, guest]
```

If the key is absent, all users have access.

---

## Grid resolution

```yaml
nx: 70   # horizontal cell count (default: 41, range 4–140)
ny: 70   # vertical cell count   (default: 41, range 4–140)
```

---

## Velocity colour scale

### Scale type

```yaml
speed_scale: percentile           # percentile | percentage of reference value | numerical value
```

### Bounds — numerical (m/s)

```yaml
speed_min: 600.0
speed_max: 1800.0
```

### Bounds — percentage of reference value

```yaml
speed_percent_min: 50
speed_percent_max: 100

# Which value is 100 %:
reference_value: sound wood velocity   # sound wood velocity | maximal velocity | upper decile
```

### Bounds — percentile

```yaml
speed_percentile_min: 10
speed_percentile_max: 90
```

## Tomogram appearance

```yaml
plot_function: velocity      # velocity | velocity square | Edyn modulus
tomogram_type: cells only    # rays only | cells only | both
shading: flat                # flat | gouraud | nearest
contourf: false              # use matplotlib contourf instead of pcolormesh
draw_boundary: false         # draw a curve along the sensor polygon
boundary_is_spline: true     # spline (true) or polygon (false) boundary
discrete_colorbar: false     # quantise the colorbar
n_discrete_colors: 5         # number of colours when discrete_colorbar is true
grid: true                   # draw grid lines on the tomogram
axes_alignment: origin bottom left
  # origin bottom left | origin in the sensors center |
  # origin in the pith | none
image_comparison_photo_tomogram: true
  # enable slider-based photo/tomogram comparison
```

## Reconstruction parameters

```yaml
anisotropy: true        # correct for acoustic anisotropy (Du 2015 formula)
rescale: true           # rescale cell speeds to match measured TOF (ERSM)
bark_thickness: 0.0     # bark thickness in cm — sensors are shifted inward
power: 1.0              # EBSI: exponent for weighted mean (range 1–5)
max_segments: 10        # ERSM: maximum ray segments (range 1–50)
e_segmentation: 0.98    # ERSM: ellipse eccentricity for segmentation
e_interpolation: 0.99   # ERSM: ellipse eccentricity for interpolation
```

## Sound-wood speed

# Node pairs used to estimate the sound-wood reference speed.

speed_method_avg: Mean    # Mean | Median

## Background photo

Registers a photo from the directory and maps two known
sensor positions to pixel coordinates so the photo can be correctly overlaid
on the tomogram.

```yaml
background:
  image: photo.jpeg          # filename
  from_node_value: 1         # node number for the first reference point
  to_node_value: 7           # node number for the second reference point
  coordinates:
    x1: 427.58               # pixel x of node from_node_value
    y1: 42.82                # pixel y of node from_node_value
    x2: 506.50               # pixel x of node to_node_value
    y2: 736.33               # pixel y of node to_node_value
```

## Resistograph settings

All `R_*` keys control the visual parameters of the resistograph display.

```yaml
R_min: 88.0              # minimum value on the resistograph scale
R_max: 180.0             # maximum value on the resistograph scale
R_depth: 25.0            # maximum drilling depth shown (cm)
R_scale_length: 25.0     # length of the reference scale bar (cm)
R_color_column_step: 300 # colour column step
R_vertical_shift: 100.0  # vertical shift of the plot
R_vertical_scale: 20.0   # zoom-out factor in the vertical direction
R_window_length: 201     # window length for the smoothing filter (odd integer)
R_polyorder: 3           # polynomial order for the Savitzky-Golay filter
R_drillbar: ['00001394', '00001400', '00001395']
  # identifiers of the drill bars to display
R_graphs: []
  # identifiers of resistograph curves to overlay
```

## Navigation / landing page

Set the tab that is shown first when the dataset is opened:

```yaml
landing_page: ERSM method   # any valid menu item name
```

Alternative low-level form (kept for compatibility):

```yaml
config:
  first_level: Tomograph
  last_sub:
    Resistograph: Define drilling paths
    Tomograph: ERSM method
```
